# Tethium

Рабочее пространство с несколькими проектами и AI-сессиями в одном окне. Java 25, Swing, SQLite, Codex CLI и Claude Code CLI. Android подключается по локальному Wi-Fi.

**Подключение телефона:** кнопка «Телефон» в левой панели → «Разрешить Wi-Fi…» → первый QR для APK → второй для привязки. [Android, обновления и сборка](docs/android.md).

## Текущий этап

Рабочее десктопное окно: компактные аккордеоны проектов, активные сессии и закреплённый снизу блок неактивных. Чат Codex получает поток ответа, сохраняет историю и черновики, поддерживает очередь сообщений и остановку. Закрытие окна не завершает ядро и работу агентов. Повторное открытие подключается к тому же ядру.

Для запуска используйте ярлык **Tethium** на рабочем столе: он открывает актуальную сборку из `desktop-active.json`, а при уже открытом окне переводит его на передний план. Установка ярлыка: `scripts/install_shortcut.ps1`. Java включена в сборку. Нужен установленный и авторизованный Codex CLI (`codex login`); для исполнителя Claude — авторизованный Claude Code (`claude`, затем `/login`).

Оформление: графитовые поверхности, светлый текст, синий акцент, общие интервалы 4/8/12/16 px. У поля сообщения единая рамка с подсветкой фокуса; скрепка добавляет пути файлов. Кнопки и навигация используют монохромные иконки, доступные названия и подсказки. Абзацы, списки, блоки кода и сообщения оформляются общими правилами `ChatTheme`; история и списки сессий не требуют горизонтальной прокрутки.

Над чатом закреплён текущий запрос: текст меняется при прокрутке его ответов. Выпадающий список показывает запросы с многострочными превью; стрелки и **Alt+PageUp / Alt+PageDown** переходят к соседним запросам. Справа от полосы прокрутки видны метки запросов по всей истории: наведение показывает текст, нажатие переводит к запросу, текущий выделен. В самой переписке нет дополнительных разделителей и номеров. Это работает и для импортированной истории; ожидающая очередь появляется только при запуске. **В конец** и **Ctrl+End** возвращают к последнему сообщению и возобновляют следование за новыми ответами. При чтении старой истории поток сохраняет положение, в том числе при раскрытии предпросмотра и горячей замене окна.

Иконки созданы встроенным `image_gen` по навыку `batch-imagegen`: один вызов, прозрачный атлас 1254×1254, 16 вырезанных PNG. [Набор на светлом и тёмном фоне](design/ui-v2/icons-v1/contact.png), [точный промпт](design/ui-v2/icons-v1/prompt.txt), [происхождение и проверенный порядок](design/ui-v2/icons-v1/provenance.json). Исходник и нарезка сохранены в `design/ui-v2/icons-v1`, ресурсы приложения — в `src/main/resources/dev/tethium/desktop/icons/v1`. `styleProbe` снимает настоящее Swing-окно с изолированными примерами проектов, тестовой квотой и без запросов к модели; снимки лежат в `.local/style/`.

`+ Проект` добавляет каталог, `+` создаёт сессию. **Enter** отправляет сообщение, **Shift+Enter** вставляет перенос строки в позиции курсора. Если в очереди уже что-то есть, Enter и кнопка **Дополнить** добавляют часть после разделителя `---` в конец последнего ожидающего сообщения. **Alt+Enter** или пункт **Отдельным сообщением в очередь** под стрелкой рядом с отправкой создаёт отдельное сообщение. Если очередь пуста, обе команды отправляют новое сообщение. Ядро выбирает актуальный конец очереди с учётом приоритета: уже выполняющееся сообщение не изменяется. Объединение работает и на паузе, не возобновляя её. Пустое сообщение не отправляется. Деактивация и переименование доступны через `⋯` и контекстное меню. Кнопка с изображением открывает опубликованные агентом HTML и изображения. Файлы можно перетащить в поле сообщения, чтобы передать агенту их пути.

Во время запуска над полем ввода видны анимированный индикатор, время работы, текущее действие и число завершённых действий. Кнопка **Действия** раскрывает последние результаты операций. Это состояние исполнения, а не оценка процента готовности. Здесь же находится очередь: **Стоп** прерывает текущую сессию и её подсессии, сохраняет их очереди на паузе. **Сейчас** или **Ctrl+Enter** останавливает ту же группу и запускает текст из поля первым, после выхода всех остановленных исполнителей. После срочного сообщения очередь продолжится автоматически. Если она была поставлена на паузу вручную, «Сейчас» выполнит только срочное сообщение, сохранив эту паузу. Пока срочная правка выполняется, остальные очереди затронутой группы временно ждут её завершения. Другие проекты и независимые сессии продолжают работу. Enter по умолчанию продолжает дополнять очередь; Shift+Enter вставляет новую строку. Прежнее сочетание Ctrl+Alt+Enter сохранено как дополнительное.

Действия очереди скрыты под **⋯** и открываются также правым кликом. Удаление требует подтверждения. **Ctrl/Shift** позволяет выбрать любые сообщения, в том числе не соседние; **Склеить** объединяет их на месте первого, **Разбить** восстанавливает исходные сообщения и их соседей. В конце составного сообщения отображается **[N]** — число отправок. После отправки выбран соответствующий элемент очереди.

В поле ввода работают **Ctrl+C/X/V**, **Ctrl+Z**, **Ctrl+Shift+Z**. Скриншот из буфера сохраняется в PNG без уменьшения разрешения; над полем появляется миниатюра с удалением. При отправке Codex получает native `localImage`, а в истории остаётся ссылка на файл. Вложения сохраняются в черновиках и переносятся при горячей замене окна. Для HTML исправлена передача фокуса между Chromium и Swing; каждому процессу GUI выделен собственный профиль браузера.

Отдельная точка справа у сессии обозначает внимание: жёлтая — незакрытый вопрос, синяя — непросмотренный результат завершённого запуска. Вопрос остаётся отмеченным до ответа. Результат считается просмотренным, когда окно активно и пользователь видит конец этой сессии. Метки сохраняются в SQLite, завершение запуска не деактивирует сессию.

Квота автоматически обновляется раз в **5 минут**. Во время чтения вращается кнопка обновления, размеры панели не меняются. Рядом компактное время последнего успешного чтения; подробности доступны в подсказке.

[256 вариантов иконки приложения в сетке 16×16](design/icon-exploration-v2/index.html): два вызова batch imagegen (240 + 16 изображений), исходные атласы, промпты и манифест нарезки сохранены рядом. Выбранная ранее медуза остаётся значком приложения, пока пользователь выбирает другой вариант.

Кнопки **↑ / ↓** в действиях очереди меняют приоритет выбранного сообщения; порядок сохраняется после перезапуска. В списке работают **Alt+↑ / Alt+↓**, а **Alt+Home / Alt+End** перемещают в начало или конец. Кнопка возврата **↶** или **Alt+Backspace** забирает последнюю добавленную часть в поле ввода, сохраняя предыдущие части в очереди. Набранный черновик сохраняется, возвращённый текст добавляется к нему через `---`. Число частей показано как [N] в конце строки сообщения. Границы отдельных отправок хранятся явно, поэтому абзацы и собственные `---` внутри текста остаются целыми. Последняя часть удаляет пустое задание из очереди. У сообщений старых версий границы отправок не были сохранены: исходный текст считается одной частью, новые дополнения к нему уже разделяются. Возврат и сохранение черновика атомарны; повтор запроса после потери ответа не извлекает ещё одну часть.

Кнопка **Раскрыть** показывает очередь целиком: сообщения сохраняют абзацы и переносят длинные строки, внутри очереди доступна вертикальная прокрутка. Её высота ограничена, поэтому поле ввода остаётся доступным. Двойной клик или **Enter** в списке также переключает раскрытие; **Ctrl+C** копирует полный текст выбранного сообщения. В свёрнутом виде показана первая строка с многоточием, если есть продолжение. Дописывание текста и обновления состояния не сворачивают очередь и не меняют выбор сообщения.

Слева под заголовком показана **квота аккаунтов**: оставшийся процент, шкала и время сброса в локальном часовом поясе. Группы лимитов переключаются списком: «Codex», «Claude» (окна 5 часов и неделя) и недельные лимиты Claude по моделям, например «Claude · Fable». Длительность лимитов берётся из ответа сервиса. Квота общая для проектов и сессий. Ядро обновляет её раз в пять минут и по кнопке обновления; события выполнения агента не запускают дополнительные чтения квоты. При ошибке связи сохранённые значения помечаются устаревшими; отсутствие данных не означает 100% остатка. Для Codex используется [официальный запрос `account/rateLimits/read`](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt), без создания разговора или запроса к модели. Для Claude ядро читает токен авторизованного Claude Code из `~/.claude/.credentials.json` и обращается к тому же сервису использования, что команда `/usage` самого CLI; токен не обновляется и не переписывается, при истёкшем сеансе показывается подсказка войти в Claude Code заново. Сбросы лимита и автоматическое ожидание квоты относятся только к Codex.

Клик по изображению или кнопка разворачивания в результатах открывает полноэкранный просмотр. **Esc** / **Вернуться** возвращает к разговору; HTML сохраняет своё состояние. Колесо масштабирует изображение относительно курсора, перетаскивание перемещает увеличенное изображение. В полном экране доступны **Вписать**, **1:1** и сброс масштаба двойным кликом. Чат переносит длинные пути и строки кода, не добавляя горизонтальную прокрутку и не меняя копируемый текст.

Все сессии работают с полным доступом: Codex запускается без песочницы (`danger-full-access`) и без подтверждений команд (`approvalPolicy=never`). Это общая настройка для данного выделенного ноутбука; она применяется к существующим, новым, импортированным и дочерним сессиям, включая продолжение разговоров. «Полный доступ» указан в меню сессии. Содержательные вопросы агента по-прежнему доступны над полем сообщения.

Модель и усилие выбираются двумя выпадающими списками в шапке. Список моделей общий для обоих исполнителей: сначала «Codex: …» и модели Codex, затем «Claude: …» и модели Claude; выбранная модель задаёт исполнителя сессии. Для Codex каталог и допустимые уровни берутся из `model/list` установленного CLI, настройки по умолчанию — из `config/read` для рабочего каталога сессии ([протокол Codex](https://learn.chatgpt.com/docs/app-server#models)). Для Claude каталог составлен из псевдонимов CLI (`fable`, `opus`, `sonnet`, `haiku`) и уровней `--effort` (`low`…`max`); настройка по умолчанию читается из `TETHIUM_CLAUDE_MODEL` или `model` в `~/.claude/settings.json`. Пункт «…: из настроек» использует настройки соответствующего CLI. Если каталог одного исполнителя недоступен, второй остаётся доступен; причина показана в подсказке.

Выбор исполнителя сохраняется для сессии, наследуется подсессиями и применяется со следующего запуска; текущий запуск завершается прежним исполнителем. При смене исполнителя усилие сбрасывается, потому что уровни разных CLI не совпадают. Новому исполнителю передаётся история сессии из Tethium (запросы, ответы другого исполнителя, результаты подсессий); при возвращении к прежнему исполнителю его разговор продолжается с тем же идентификатором и получает только пропущенные сообщения. Ответы в чате подписаны именем исполнителя. Claude запускается через Claude Code в режиме `-p` с потоковым JSON: тот же локальный MCP-сервис Tethium, вопросы `AskUserQuestion` отображаются над полем ввода как обычные вопросы агента, остановка выполняется через управляющий запрос `interrupt`, вызовы инструментов показываются в действиях запуска. Полный доступ для Claude означает `bypassPermissions`. В Android-клиенте тот же объединённый список моделей и тот же экран квоты. При смене модели несовместимое усилие возвращается в автоматический режим. Выбор сохраняется отдельно для каждой сессии, наследуется подсессиями и применяется со следующего запуска, в том числе к ожидающей очереди. Уже выполняющийся запуск сохраняет свои настройки. Сохранённые неизвестные модели не подменяются другой моделью при ошибке загрузки каталога; списки временно недоступны и автоматически переподключаются. Просмотр каталога не запускает модель.

Сборка и запуск из исходников:

```powershell
.\gradlew.bat test
.\gradlew.bat run --args="C:/git/Tethium"
.\gradlew.bat packageDesktop
.\gradlew.bat desktopProbe
.\gradlew.bat uxProbe
.\gradlew.bat quotaProbe
.\gradlew.bat desktopProbe -Preal
.\gradlew.bat agentProbe -Pagent=codex
.\gradlew.bat previewProbe
```

Для сборки нужен JDK 25; Gradle использует Java toolchain. Wrapper закреплён на Gradle 9.8.2 с SHA-256 дистрибутива. `test` и `desktopProbe` не обращаются к моделям. `desktopProbe -Preal` и `agentProbe` используют текущую авторизацию CLI и расходуют лимит аккаунта. Реальная проверка GUI создаёт файлы только в отдельном каталоге `.local/desktop/`.

При обновлении запущенного приложения используйте отдельный каталог: `.\gradlew.bat packageDesktop -PdesktopDestination=desktop-quota-20261102`. Не пересобирайте поверх каталога работающего окна или ядра. `uxProbe` использует изолированную базу и тестовый исполнитель, проверяет размеры окна, полноэкранный просмотр, сохранение очереди и продолжение работы; снимки и отчёт находятся в `.local/ux/`. `quotaProbe` читает реальную квоту авторизованного Codex и проверяет её отображение с изолированным ядром, не создавая запуск модели; результат в `.local/quota/`.

Обновление ставится командой `scripts/request_desktop_update.ps1 -AppPath <новая сборка/Tethium.exe> -SessionId <сессия>`. Заявка сохраняется на диске, один фоновый диспетчер выполняет `reload_desktop.ps1`. Если ожидают несколько сборок, устанавливается последняя. После перезагрузки компьютера незавершённая заявка возобновляется при открытии Tethium. Ошибочная установка сохраняет диагностику и не повторяется бесконечно. Сначала кандидат проверяется на согласованной копии SQLite без запуска агентов; затем второй GUI получает реальное состояние, принимает черновики, выбранную сессию, размеры окна, положение разговора, предпросмотр и раскрытие очереди. Прежнее окно закрывается только после подтверждения готовности нового. Ошибка кандидата оставляет прежнюю версию доступной. HTML-предпросмотр при замене процесса загружается заново; внутреннее JavaScript-состояние страницы не переносится.

Сборка содержит отдельные отпечатки GUI и ядра. При изменении GUI работающий процесс ядра сохраняется. Каждый новый запуск Codex обслуживает отдельный процесс `WorkerMain`: он держит stdio агента и постоянный локальный MCP-адрес, записывает события в собственный журнал и ждёт ответы на вопросы независимо от ядра. При одинаковом `workerProtocol=1` ядро передаёт запуски без ожидания окончания ответа. Новое ядро открывает рабочую базу после освобождения `host.lock`, подхватывает исполнителей и продолжает обработку событий с сохранённой позиции. Вызовы инструментов и их результаты фиксируются одной транзакцией; повторное чтение не повторяет изменение. Во время короткого отсутствия ядра ответы накапливаются, а обращения к его инструментам ждут подключения. Пользовательская пауза сохраняется. Для первого перехода со старого ядра и несовместимого протокола остаётся drain — завершение текущих запусков с удержанием новых поручений в очереди. Копия базы перед заменой сохраняется для восстановления.

Заявка — `%LOCALAPPDATA%/Tethium/desktop-update-request.json`; статус — `.local/desktop-update/status.json`; активный GUI — `%LOCALAPPDATA%/Tethium/desktop-active.json`. `handoff` означает замену ядра с сохранением исполнителей. `waiting-for-runs` относится к первому переходу или несовместимому протоколу: новое окно уже работает, ядро ждёт только текущие запуски. Прямой `reload_desktop.ps1` поддерживает `-DesktopOnly`, `-ForceCore` и `-WaitForLock`. Проверка упакованных процессов: `powershell -File scripts/probe_reload.ps1 -AppPath <сборка/Tethium.exe>`; проверка сохранения заявки и выбора последней сборки — `scripts/probe_update_requests.ps1`.

Данные хранятся в `%LOCALAPPDATA%/Tethium`: `tethium.db` — история и очередь, `host.log` — журнал ядра, `workers/<runId>/` — отдельные журналы исполнителей. Каталог можно переопределить Java-параметром `-Dtethium.data=...`. Команда **Завершить ядро и все запуски** в меню `⋯` останавливает всё приложение. Аварийное завершение только ядра сохраняет работающих исполнителей; следующее ядро подхватывает их, включая уже завершившиеся ответы. Если погиб сам исполнитель или перезагрузился компьютер, сохраняется полученный текст, а неопределённый запуск не отправляется модели повторно. Перезапуск компьютера не сохраняет выполняющиеся команды. Старые пакеты нельзя удалять, пока их используют исполнители.

HTML-просмотр при первом использовании скачивает и кэширует Chromium. `previewProbe` проверяет HTML/CSS/JavaScript, изображения и связанные ресурсы в скрытом Swing-окне. Отчёт сохраняется в `.local/preview/`; результаты CLI — в `.local/probes/`, проверки окна — в `.local/desktop/`. Эти каталоги исключены из Git.

Пути к CLI можно задать через `TETHIUM_CODEX` и `TETHIUM_CLAUDE`, модели — через `TETHIUM_CODEX_MODEL` и `TETHIUM_CLAUDE_MODEL`. По умолчанию используются настройки установленных CLI.

[Результаты интеграционных проверок и оставшиеся работы](docs/integration-probes.md)

## Архитектурные решения

Десктопный интерфейс — Swing. Исполнители — установленные Codex CLI и Claude Code CLI; исполнитель выбирается для каждой сессии и может меняться между запусками. Android подключается по локальной сети через отдельный HTTPS-шлюз с привязкой по QR. Административное API остаётся на loopback.

Один проект соответствует одному корневому Git-каталогу. По умолчанию все его сессии работают в этом каталоге. Tethium не создаёт worktree автоматически и не требует отдельного worktree на сессию. Агент может создать или выбрать worktree по указанию пользователя; такая сессия остаётся частью исходного проекта. Идентификатор проекта и фактический рабочий каталог запуска хранятся отдельно.

Сессии одного проекта должны видеть друг друга на уровне агентов, включая сессии, работающие в разных worktree. Ядро предоставляет общий реестр сессий: идентификатор, название, активность, состояние текущего запуска, рабочий каталог и последнее обновление. Агент может получить список соседних сессий и прочитать их доступную историю и результаты по запросу. Список и история принадлежат проекту; собственный контекст разговора остаётся у каждой сессии. История деактивированных сессий также доступна по запросу.

Видимость сессий не означает автоматического объединения их контекстов или изоляции изменений файлов. В общем каталоге изменения одной сессии доступны остальным. Завершение запуска агента не меняет активность сессии; деактивация остаётся явным действием пользователя.

Смена исполнителя Codex ↔ Claude внутри одной сессии реализована: сессия хранит исполнителя в настройках, запуск фиксирует его, разговоры каждого CLI привязаны к сессии отдельно. Для перехода на собственный GUI добавлен перенос переписки из Nimbalyst: сообщения пользователя и ассистента, ответы на формы и заметка о текущем состоянии. Исходная беседа сохраняется, Tethium продолжает работу в собственном разговоре Codex с перенесённым контекстом.

Перенос выполняет [scripts/import_nimbalyst.py](scripts/import_nimbalyst.py) через авторизованное API ядра. Скрипт открывает базу Nimbalyst только на чтение, сохраняет локальную JSON-копию в `.local/imports/` и импортирует сообщения с исходными идентификаторами. Повторный импорт не дублирует их и не запускает модель. Можно открыть нужную сессию аргументом `Tethium.exe --session=<id>`.

Агенты должны уметь передавать работу другим сессиям и создавать подсессии. Подсессии видны пользователю и принадлежат тому же проекту.

В первый интерфейс входят разговоры и просмотр созданных агентами изображений и HTML. Редактор кода, общий файловый браузер, просмотр diff, терминал и Git-интерфейс отложены.

### Рабочая схема реализации

Следующие детали описывают рабочую схему и дальнейшее развитие. Ограничения перечислены в отчёте проверок.

**История и смена исполнителя.** Источник общей истории — Tethium. Сессия хранит сообщения, события, результаты инструментов, ссылки на артефакты и связи с подсессиями. Каждый запуск фиксирует исполнителя и модель; идентификаторы разговоров конкретного CLI хранятся отдельно. При смене исполнителя адаптер открывает его разговор и передаёт контекст из истории Tethium: исходные требования, принятые решения, результаты и незавершённую работу. Большая история передаётся через сводку и последние сообщения, с доступом к подробностям по запросу. При возвращении к ранее использованному исполнителю его сохранённый разговор получает события, появившиеся за время отсутствия. Внутреннее состояние одного CLI не считается переносимым в другой.

**Запуски и доставка работы.** В одной сессии одновременно выполняется один запуск; разные сессии могут работать параллельно. Смена исполнителя применяется к следующему запуску после завершения или остановки текущего. Сообщения и поручения сохраняются в очереди с автором, адресатом и идентификатором доставки. Обычное сообщение и поручение, запускающее работу, различаются. Занятая сессия получает поручение после текущего запуска; свободная активная сессия может начать его сразу. Деактивированные сессии сами не возобновляются.

**Подсессии.** Созданием и выполнением подсессий управляет ядро Tethium. Дочерняя сессия хранит `parentSessionId`, имеет собственную историю и может использовать другого исполнителя. По умолчанию она наследует проект и выбранный рабочий каталог родителя. Результат поручения возвращается родителю отдельным событием с привязкой к поручению. Родитель может ждать результат или продолжать другую работу. Завершение дочернего запуска не деактивирует дочернюю сессию. Предел параллельных запусков задаётся в ядре.

**Инструменты Tethium.** Общий локальный MCP-сервис предоставляет обоим агентам операции просмотра сессий и истории, отправки сообщений, передачи работы, создания подсессий и регистрации артефактов. Идентификаторы вызывающей сессии и проекта задаёт ядро. Поддержка MCP документирована у [Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) и [Claude Code](https://code.claude.com/docs/en/mcp).

**Адаптеры.** Для Codex используется [app-server](https://learn.chatgpt.com/docs/app-server) через stdio: создание и продолжение разговоров, запуск и остановка работы, поток событий и запросы решений пользователя. Для Claude используется [Claude Code в программном режиме](https://code.claude.com/docs/en/headless) через stdio: `--input-format stream-json`, `--output-format stream-json`, продолжение через `--resume`, новый разговор получает `--session-id`, вопросы и запросы разрешений приходят управляющими запросами `can_use_tool` (`--permission-prompt-tool stdio`), остановка — управляющим запросом `interrupt`. Вызовы инструментов Claude нормализуются к элементам Codex (`commandExecution`, `fileChange`, `mcpToolCall`, `webSearch`), поэтому ядро, история и GUI не различают исполнителей. Конфигурация MCP передаётся временным файлом, токен — окружением процесса. Проверенные версии зафиксированы в [отчёте интеграции](docs/integration-probes.md).

**Просмотр результатов.** Артефакт связывает сессию, запуск, тип содержимого и файл либо набор файлов на ноутбуке. Клиенты получают его через API ядра по идентификатору, поэтому Android не зависит от локальных Windows-путей. HTML поддерживает собственные стили, скрипты и связанные ресурсы в пределах зарегистрированного набора файлов. Предпросмотр отделён от управляющего API приложения и не получает его учётные данные. Для Swing выбран Chromium через JCEF; [IntelliJ Platform использует JCEF для встроенного браузера](https://plugins.jetbrains.com/docs/intellij/embedded-browser-jcef.html). Совместимость standalone-сборки JCEF с Java 25 проверена на Windows x64. Упаковка готового приложения с нативными библиотеками остаётся отдельной работой.

Ядро предоставляет `session_list`, `session_history`, `session_message`, `session_delegate`, `session_spawn`, `session_rename`, `session_directory` и `artifact_publish`. Одновременно выполняются до 16 запусков на все проекты и не более одного в сессии. Результат поручения добавляется в историю отправителя и попадает в контекст его следующего запуска. Подсессии видны в дереве; завершение ответа не деактивирует их. Сессии проекта с галкой «ставить задачи сессиям других проектов» в настройках проекта также получают `cross_project_sessions` и `cross_project_delegate`. Галка хранится в базе Tethium и по умолчанию выключена.

## Макет

[Открыть макет проектов и сессий](design/tethium.mockup.html "width=1200 height=820")

Главная навигация — вертикальный аккордеон проектов. Несколько проектов можно раскрыть одновременно; внутри находятся их активные сессии. Выбранная сессия занимает основную область окна.

Компактная компоновка: сессии в одну строку, узкая боковая панель, небольшие заголовки и однострочное поле ввода. Состояние сессии обозначено индикатором; полная подпись доступна при наведении и скринридеру. На сенсорных устройствах строки увеличены для удобного нажатия.

Сессия остаётся активной, пока пользователь явно не нажмёт «Деактивировать». Состояния «ассистент работает», «ждёт ответа» и «ответ завершён» не меняют активность сессии.

Деактивированные сессии находятся в отдельном аккордеоне, сгруппированном по проектам. Этот блок по умолчанию свёрнут и закреплён внизу боковой панели. Он не уезжает при прокрутке активных проектов. Историю деактивированной сессии можно открыть; для продолжения её нужно активировать.

Канбан исключён из текущего макета. Сейчас проектируем только проекты и сессии.

Работают раскрытие проектов, выбор и создание сессий, добавление демонстрационных проектов, сообщения и черновики по сессиям, деактивация и обратная активация. Кнопка «Завершить ответ · демо» показывает, что завершённая работа не убирает сессию из активных. На Android сначала показан список проектов, затем открывается выбранная сессия; кнопка возврата ведёт обратно к аккордеонам.

Это автономный HTML-макет с демонстрационными данными, без Java-приложения, выполнения кода и реальной синхронизации. Переключение «Ноутбук / Android» использует одно состояние макета; перезагрузка страницы сбрасывает изменения. Открывается в Nimbalyst и обычном браузере без установки зависимостей.


Подробности новых возможностей: [цитаты, Markdown, расход токенов, ожидание квоты, GitHub и Tethium Remote](docs/clients-and-usage.md).

### Пауза очереди и Android-приложения

«Пауза» рядом с очередью задерживает следующие сообщения, не отменяя текущий ответ. «Продолжить» доступна и во время ответа, и при пустой очереди. «Стоп» по-прежнему отменяет выполнение и сохраняет очередь на паузе. Раскрытие очереди одновременно показывает полный текст и кнопки действий.

На Android: меню → «Приложения и обновления». Tethium проверяет обновления при работе (раз в 5 минут) и фоновым заданием Android по Wi-Fi (интервал 15 минут, фактическое время зависит от ОС). Для каждого приложения есть переключатель автообновления. Новые приложения устанавливаются только по кнопке. Обновления уже установленных приложений могут устанавливаться автоматически; при требовании Android появляется подтверждение. Сам Tethium автоматически заменяется только в фоне, чтобы не закрыть редактор во время набора. Разрешение «Установка неизвестных приложений» выдаётся Tethium в системных настройках. Проверяются SHA-256, имя пакета, версия и совпадение подписи; смена ключа и понижение версии запрещены.

Скрипт сборки проекта публикует подписанный standalone APK в `.tethium-apps.json` в корне проекта (split APK/AAB не поддерживаются). APK должен лежать внутри проекта. Можно вызвать:

```powershell
python C:/git/Tethium/scripts/publish_android_app.py --project C:/git/MyGame --apk C:/git/MyGame/app/build/outputs/apk/release/app-release.apk --title "Моя игра"
```

Скрипт читает packageName/versionCode/versionName из APK через Android SDK aapt2 и атомарно обновляет каталог. Следующая сборка с большим versionCode и прежним ключом подписи появляется на телефоне без обновления Tethium. Раздача каталога и APK доступна только привязанным устройствам по HTTPS. Для работы нужны включённый ноутбук и локальная сеть.


### Диагностика скачков чата

GUI автоматически пишет локальный кольцевой журнал в `%LOCALAPPDATA%/Tethium/diagnostics/chat-layout/` (Remote — в собственном каталоге данных). Сохраняются причины замен HTML, версии и диапазоны загруженной истории, длительность рендера, геометрия текста/viewport/scrollbar, якорь видимого фрагмента, решения восстановления позиции и перехода к концу, стек заметных перемещений, отметки мыши/клавиатуры. Текст сообщений, HTML и нажатые символы не записываются. Геометрия снимается раз в 250 мс при изменениях, сводка счётчиков — раз в 30 секунд. Запись асинхронная, очередь ограничена; пропуски учитываются. Сегменты по 2 МиБ, суммарно около 64 МиБ, старше 7 дней удаляются при ротации. В журнале есть PID GUI, версия сборки, sessionId и время.

После жалобы соберите последние 10 минут (не требуется воспроизводить проблему):

```powershell
python scripts/chat_layout_report.py --session a7e50fec-0973-455c-b21b-e1ad43c9daa1 --minutes 10
```

`--at 2026-11-03T13:00:00+01:00` задаёт конец интересующего интервала. Отчёт показывает причины перестроений, изменения ширины, перемещения без недавнего ввода и быстрые смены направления. Это диагностические кандидаты: следование концу и явный переход к запросу тоже меняют прокрутку. Для точного разбора рядом остаются исходные JSONL-события. Журнал начинает собираться после установки этой версии; задним числом события не восстанавливаются.


Android 0.4.1 использует тот же реестр `identity/v3/names.properties` и PNG 88 px, что и десктоп; Gradle копирует их в APK при сборке. Модель/усилие сохраняются после подтверждённого ответа ядра; JSON `null` означает «Авто», строка `"null"` нормализуется. Совместимое усилие не сбрасывается при смене модели. Несовместимое остаётся видимым и требует явного выбора. Загрузка каталога, сохранение настроек, команды очереди, открытие результатов и установка приложений защищены от повторных нажатий; кнопка показывает выполнение и восстанавливается при ошибке.


### Локальный магазин APK

Android 0.4.2: меню → «Магазин приложений» показывает приложения всех зарегистрированных проектов, включая установку, открытие и автообновление каждого приложения. Новые приложения устанавливаются вручную. Одинаковый `versionCode` у разных dev-сборок поддержан кнопкой «Переустановить»; автоматическое обновление требует увеличения номера. Другая подпись и понижение версии не допускаются. Подтверждение Android показывается по требованию ОС.

Агент проекта публикует завершённую сборку инструментом `app_publish(path, title)`. Пакет, версия и подпись проверяются Android SDK build-tools; APK копируется в `.tethium/apps/<sha256>.apk`, исключённый из Git. `.tethium-apps.json` в корне проекта обновляется атомарно. Исходный APK можно пересобирать — опубликованная копия останется неизменной. Публикация сама ничего не устанавливает на устройства.

Из скрипта сборки используйте `python C:/git/Tethium/scripts/publish_android_app.py --project <каталог> --apk <APK> --title <название>`: скрипт обращается к работающему Tethium. Для APK из другого проекта вызовите его с тем проектом. HTTP API для локальных интеграций: `POST /projects/<id>/app-publish` с `path` и `title`. Android видит каталог после обновления списка, менять или пересобирать Tethium для каждой новой игры не требуется.


Android 0.4.3: исправлено падение при обновлении иконок проекта/сессии — Android ICU не поддерживает Java-флаг `(?U)`, поэтому нормализация имени теперь выполняется без regex. Основные меню оформлены компактными панелями с группами действий, иконками и явными переключателями; поля и подтверждения получили общие отступы. Падение 0.4.2 воспроизведено на Android 35; в 0.4.3 каталог открывается и переживает обновления состояния без исключений.

Интерактивные панели проектов: [контракт `.tethium/panel.json` и пример CADabro](docs/project-panels.md). Панель открывается на всю рабочую область или рядом с сессией.

Отложенные задачи по умолчанию допускают замену исполнителя при недостаточной квоте:
**Astra ↔ Fable**, **Sol (GPT-6.1) ↔ Opus**. Сначала используется модель сессии;
её пара выбирается, если проходит порог квоты задачи. Неизвестная/устаревшая квота
не считается свободной. Другие семейства автоматически не заменяются.
В редакторе задачи можно снять «Автоматически менять исполнителя по квоте» либо
закрепить конкретную модель. На Android это пункт «Исполнитель…» в действиях задачи.
Уже существующие ожидающие задачи получают автозамену по умолчанию.
Выбор записывается только в задание, переживает перезапуск ядра и не меняет модель
сессии для следующего обычного сообщения. CPU-условия, приоритеты, лимит параллелизма
и ручные паузы сохраняются. Отменённые/упавшие задачи сами не возобновляются.

Файловый менеджер: меню `⋯` → «Файлы…» на компьютере, меню → «Файлы» на Android.
Обмен файлами и папками между телефоном, рабочим ноутбуком и Tethium Remote,
прогресс и продолжение передачи описаны в [документации](docs/file-manager.md).
