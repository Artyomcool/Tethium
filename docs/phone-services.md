# Связь телефона с сервисом проекта через Tethium

Если у проекта есть локальный сервис и своё Android-приложение, связь между ними целиком берёт на себя Tethium. Проекту не нужны свой порт для локальной сети, правило брандмауэра, адрес ноутбука в настройках, привязка и токены: приложение передаёт запрос приложению Tethium на телефоне и получает ответ сервиса.

## Сторона ноутбука

Агент проекта вызывает инструмент `phone_service_publish` с именем сервиса, портом и пакетом приложения. Инструмент записывает `.tethium/service.json` и возвращает исходник клиента:

```json
{ "services": [ { "name": "ahchecklist", "port": 8086, "packages": ["ahlist.mobile"] } ] }
```

Сервису достаточно слушать `127.0.0.1`. Адрес `0.0.0.0` нужен, только если остаётся отдельный доступ из браузера. Запускает сервис сам проект. Если он не запущен, приложение получит ответ 503. Если два проекта объявят одно имя, действует первый в списке.

## Сторона телефона

APK публикуется через `app_publish`: связь работает только для пакета и ключа подписи, которые опубликовал этот проект.

Клиент `TethiumLink.java` копируется в приложение, в нём меняется только строка `package`. В манифест добавляется:

```xml
<queries><provider android:authorities="dev.tethium.mobile.link"/></queries>
```

Запрос, вызывать вне главного потока:

```java
try (TethiumLink.Response response = TethiumLink.request(context, "ahchecklist", "POST", "/api/lists", Map.of("Content-Type", "image/jpeg"), photo)) {
    int status = response.status;
    byte[] answer = response.bytes();
}
```

Статус, заголовки и тело приходят от сервиса как есть. Если запрос не удалось доставить, бросается `TethiumLink.Unavailable` с полем `reason`:

| Значение | Что значит |
|---|---|
| `no_tethium` | Tethium на телефоне не установлен |
| `not_paired` | Tethium не привязан к ноутбуку |
| `denied` | Сервис не объявлен, либо пакет или подпись не совпали с опубликованными |
| `unreachable` | Ноутбук недоступен |
| `bad_request` | Некорректный метод или путь |

Поддерживаются методы GET, POST, PUT, DELETE, HEAD и OPTIONS. Заголовок `Authorization` приложения отбрасывается.

## Что происходит внутри

Приложение Tethium узнаёт вызывающий пакет и его подпись у Android и получает у ноутбука токен для этого сервиса. Токен хранится только в Tethium, а если он отозван, запрос повторяется с новым. На ноутбуке шлюз пробрасывает `http://<ноутбук>:8766/svc/<имя>/<путь>` на `http://127.0.0.1:<порт>/<путь>`, и сам сервис токена не видит.

Тела запроса и ответа передаются через файлы во временном каталоге Tethium. Поэтому прогресс отправки в приложении показывает только передачу в Tethium, а не в сеть.

## Границы

- Токен открывает один сервис и не даёт доступа к сессиям Tethium. Токен устройства не открывает сервисы.
- «Отключить все телефоны» на ноутбуке отзывает и токены сервисов.
- Соединение без TLS, как и весь обмен с телефоном: только домашняя сеть.
