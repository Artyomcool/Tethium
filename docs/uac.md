# Подтверждение UAC с телефона

Мобильный шлюз передаёт структуру настоящего диалога UAC: его заголовок, доступные тексты и кнопки. Android показывает их в собственной панели. Названия и действия берутся из Windows UI Automation; модели, OCR и угадывание координат не используются.

В приложении есть пункт «Запрос UAC» в меню. При открытом запросе над разговором появляется отдельная кнопка. Ссылка работает, пока приложение подключено к ноутбуку; отдельного фонового Android-сервиса уведомлений в этой версии нет.

## Установка помощника

Для защищённого рабочего стола нужен процесс SYSTEM в интерактивной сессии владельца. Для этого устанавливается отдельная служба `TethiumUac`, которая запускает ограниченный помощник на `WinSta0\Winlogon`. Первое подтверждение установки выполняет пользователь на ноутбуке.

```powershell
powershell -File scripts/build_uac.ps1 -Destination build/uac-helper
powershell -File scripts/install_uac.ps1 -HelperPath build/uac-helper/TethiumUac.exe
```

Нужен установленный .NET Framework 4.x с UI Automation (штатный компонент Windows). Служба устанавливается в `%ProgramFiles%\Tethium UAC`, настройки и локальный дескриптор — в `%ProgramData%\Tethium\Uac`. Владельцу разрешено чтение, SYSTEM и администраторам — изменение. Исполняемые файлы именуются по хешу; установщик не переписывает работающий EXE. Результат запроса повышения прав записывается в `%LOCALAPPDATA%\Tethium\uac-install-state.json`, результат установки — в `install-result.json` служебного каталога. `packageDesktop` включает EXE и установщик в ресурсах `native/uac/`.

Отключение и удаление регистрации службы:

```powershell
powershell -File scripts/install_uac.ps1 -HelperPath build/uac-helper/TethiumUac.exe -Disable
```

## Область доступа

- Помощник обрабатывает только видимые окна системного `%WINDIR%\System32\consent.exe`, работающего под SYSTEM, только на защищённом рабочем столе и в активной консольной сессии указанного владельца. Экран входа и окна других программ не обрабатываются.
- Служба не принимает команды запуска программ, произвольные координаты, клавиши или текст. Она читает структуру окна и вызывает поддерживаемые кнопки этого окна по отдельному человеческому нажатию.
- При наличии поля пароля/редактирования мобильное подтверждение недоступно. Учётные данные вводятся на ноутбуке.
- ID запроса и кнопок случайные. Перед ответом помощник повторно проверяет содержимое, runtime ID элементов, HWND, PID и время создания процесса. Изменившиеся, закрытые и уже использованные запросы отклоняются; сетевые ошибки не приводят к автоматическому повтору ответа.
- Только привязанные клиенты мобильного шлюза получают `/uac` и `/uac/answer`. Эти команды отсутствуют в API ядра и инструментах агентов. Локальная служба принимает запросы лишь на loopback с отдельным ключом; ключ не передаётся телефону. Мобильный транспорт сохраняет выбранную владельцем конфигурацию домашней LAN.
- Если UI Automation не отдаёт доступных кнопок, приложение сообщает об этом; автоматического нажатия или догадки по изображению нет.

Целевые проверки: `UacBridgeTest`, `MobileGatewayTest.uacStatusIsPushedToPairedClientsAndActionsAreNotHostCommands` и `TethiumUac.exe --self-test`. Реальную структуру и ответ необходимо проверять отдельным безвредным запросом UAC с ручным ответом пользователя.
