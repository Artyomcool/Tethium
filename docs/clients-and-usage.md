# Клиенты, квота и GitHub

## Разговор и результаты

Выделите часть сообщения и нажмите «Цитировать» над разговором, пункт контекстного меню или Ctrl+Shift+Q. Цитата вставляется в текущий черновик. На Android — долгое нажатие по тексту, выделение, «Цитировать».

Enter дополняет последний пункт очереди, Alt+Enter (включая правый Alt/AltGr) создаёт отдельный пункт, Shift+Enter вставляет перенос, Ctrl+Enter отправляет срочную правку с остановкой текущего исполнения. Markdown (.md/.markdown, регистр не важен) открывается во встроенном просмотре с относительными изображениями и ссылками, как HTML.

## Расход токенов

Нажмите заголовок «Квота Codex» слева или контекстное меню проекта/сессии → «Токены и CPU». На Android — меню сессии → «Токены и CPU». Можно выбрать проект, сессию и период: с последнего сброса или всё время; доступны точные зарегистрированные счётчики, доля и график накопленного расхода.

Счётчики приходят из `thread/tokenUsage/updated`; известные Tethium разговоры и их дочерние native threads также восстанавливаются из локальных Codex JSONL. Импорт повторяется раз в пять минут без дублирования. Сравнение накопленных счётчиков выполняется до фильтрации дат: старый контекст не считается повторно при переподключении. Кэш входит во входящие токены, reasoning — в исходящие. Доля считается среди учтённых разговоров Tethium, а не среди всех расходов аккаунта и не как процент квоты. Удалённые исходные журналы и чужие разговоры нельзя восстановить; неполная доступная история обозначается в окне.

Автопродолжение включается отдельно в меню каждой сессии. При исчерпании квоты текущая задача сохраняется в очереди, появляется «Ждём квоту». После свежего подтверждения доступной квоты сессия продолжает работу. Ручной Stop и пауза имеют приоритет, деактивированные сессии не запускаются. Опрос квоты — раз в пять минут; проверка сохранённого состояния ожидания не делает дополнительных запросов к Codex.

Если Codex возвращает число доступных сбросов, оно показано как «Неделя [N]». При остатке ≤5% нажатие метки открывает действие сброса, затем обязательное подтверждение расхода. Повтор запроса использует тот же UUID, сохранённый клиентом и ядром. Реальный кредит при автоматических проверках не расходуется. Если аккаунт/версия CLI не предоставляет количество, приложение не придумывает его.

## GitHub

Добавление проекта и его контекстное меню → «Настройки проекта и GitHub» позволяют создать репозиторий через `gh`, выбрать приватность и включить частые commit/push. По умолчанию репозиторий приватный; создание подключает `origin`, но не коммитит рабочие файлы автоматически.

Единственный источник правила — управляемый блок `tethium:github-sync` внутри корневого AGENTS.md. Переключатель редактирует только этот блок; остальной файл сохраняется. При старте/продолжении агент получает короткое указание перечитать актуальный AGENTS.md, а не повтор полной скрытой политики. При выключении старое управляемое правило явно отменяется в контексте следующего запуска.

Нужна авторизация GitHub CLI на ноутбуке. Tethium ищет `TETHIUM_GH`, стандартную установку, затем `%LOCALAPPDATA%/Tethium/tools/gh/bin/gh.exe`, затем PATH. Для установленной переносимой версии вход:

```powershell
& "$env:LOCALAPPDATA/Tethium/tools/gh/bin/gh.exe" auth login --hostname github.com --web --git-protocol https
```

Папка переносимого `gh` добавляется в PATH дочерних исполнителей Tethium. Настройка правила не включается автоматически для всех существующих проектов.

## Tethium Remote для Windows

Это отдельный пакет с тем же Swing-интерфейсом и серебристой медузой. Пакет не содержит HostMain, адаптеров Codex/Claude, SQLite-хранилища сессий или CLI. Основное приложение обозначено кислотно-зелёной медузой.

1. На ноутбуке откройте «Телефон». Ссылка первого QR открывает страницу загрузки Android и Windows-клиента.
2. На другой Windows-машине скачайте ZIP, распакуйте и запустите `Tethium Remote.exe`. Java 25 включена в пакет.
3. Скопируйте свежую ссылку привязки из второго QR/поля на ноутбуке в окно Remote. Ссылка одноразовая: для каждого нового устройства нужна новая.

Обе машины находятся в одной LAN. Соединение идёт по обычному HTTP внутри домашней сети без TLS; единственный секрет — токен привязки из ссылки, привязка хранится локально в `%LOCALAPPDATA%/TethiumRemote`. Черновики и вложения клиента отделены от черновиков ноутбука. Сервер продолжает работать при закрытом клиенте.

Агент публикует JAR, EXE или ZIP обычным `artifact_publish`. На удалённом клиенте выберите результат → «Получить» либо «Получить и запустить». Проверяются размер и SHA-256; ZIP распаковывается с защитой от выхода за каталог. При нескольких точках входа клиент предлагает выбрать. JAR запускается комплектной Java 25 на принимающей машине, EXE — напрямую; лог находится рядом со сборкой в `tethium-launch.log`. Запуск выполняется только по нажатию пользователя. Для проекта с зависимостями публикуйте исполняемый fat JAR либо ZIP с JAR/ресурсами/нужной структурой каталогов.

Сборка: `gradlew.bat packageRemote -PremoteDestination=remote-<версия>`. Архив готового каталога `Tethium Remote` размещается в `%LOCALAPPDATA%/Tethium/releases/tethium-remote.zip`, откуда его отдаёт установочная LAN-страница. Удалённый клиент не обновляет сам себя автоматически в этой версии. Android 0.3.0 получает обычное подписанное обновление с ноутбука.
