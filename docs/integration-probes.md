## Устройство прототипов

- `agent` — отдельные адаптеры, обмен JSON через дочерние процессы, поток событий, отмена и обработка завершения. Процессы запускаются без оболочки, аргументы передаются списком. Для Windows конфигурация MCP у Codex передаётся отдельными параметрами; у Claude — временным JSON-файлом. Токен локального MCP передаётся окружением дочернего процесса.
- `core` — SQLite, идентификаторы проекта/сессии/родителя, независимая активность, история с авторством, отдельные привязки к разговорам провайдеров и позиции полученной истории. Уникальный индекс запрещает два одновременных запуска одной сессии. Сохранение результата, привязки и завершения запуска выполняется одной транзакцией.
- `host` — постоянный процесс с эксклюзивной блокировкой базы, loopback API, очередью и пределом в четыре параллельных запуска. Одна сессия выполняет одно поручение за раз. При аварийном восстановлении сохраняет частичный ответ и помечает незавершённые запуски прерванными.
- `desktop` — компактное Swing-окно с FlatLaf, деревом проектов, чатом Markdown, черновиками, очередью, остановкой, запросами разрешений и просмотром результатов. Окно переподключается к существующему ядру. Состояние обновляется раз в 500 мс.
- `tools` — локальный MCP HTTP endpoint, привязанный ядром к вызывающей сессии и её проекту. Реализованы чтение списка и истории, сообщения, поручения, подсессии, переименование, смена рабочего каталога в том же Git-проекте и регистрация артефактов. Чужой проект недоступен.
- `artifact` — отдельный HTTP origin для одного набора файлов; проверка канонического пути ограничивает доступ этим набором. Предпросмотр не получает токен управления сессиями.
- `probe` — явные команды проверки CLI и Chromium. Автоматические тесты не обращаются к моделям и используют отдельные тестовые процессы с детерминированными JSON-транскриптами.

Большой контекст сейчас передаётся как начало и конец транскрипта с явным обозначением пропуска; оставшаяся история доступна инструментом. Автоматическое смысловое сжатие пока не реализовано.

## Проверки без обращения к моделям

`gradlew.bat test` проверяет сохранность сессий после перезапуска, явную деактивацию, ограничение параллельных запусков, возврат к прежнему провайдеру, освобождение сессии после ошибки исполнителя, авторизацию MCP и границы проекта, HTTP-предпросмотр и выход за пределы набора файлов. Отдельные тестовые процессы проверяют JSON-RPC, перемежающиеся уведомления, фильтрацию чужого thread ID, отмену обоих адаптеров, отсутствие двойного текста Claude и ошибочный результат с `subtype=success`, но `is_error=true` — именно такую комбинацию вернул установленный Claude при исчерпанном лимите.

## Следующие работы

1. После восстановления лимита Codex выполнить `gradlew.bat agentProbe -Pagent=both` — реальную проверку смены исполнителя внутри одной сессии. Отдельная панель квоты Claude и выбор исполнителя в Android-клиенте пока не сделаны: телефон получает каталог текущего исполнителя сессии, но его подписи говорят о Codex.
2. Android-клиент, аутентификация устройств по LAN и доставка файлов артефактов с ноутбука.
3. Обновления состояния без опроса, постраничная загрузка длинного чата, смысловая сводка для передачи контекста.

Сейчас HTML использует отдельный локальный origin, а desktop читает изображения с локального диска. Chromium кэшируется при первом открытии HTML. Работа с файлами и команды выполняются через Codex; встроенного редактора, терминала и Git-интерфейса нет. Завершение дочернего поручения записывается родителю в историю, но само по себе не запускает новый ответ родителя.
